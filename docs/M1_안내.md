# M1: 방 번호로 1:1 대전 — 시험 안내와 구현 메모 (2026. 11. 19.)

## 파일
| 파일 | 하는 일 |
|---|---|
| `versus.html` | **자동 생성.** `index.html`을 그대로 복제하고 아래 파일만 덧붙임 (`python3 tools/build_versus.py`) |
| `versus/vs.js` | 대전 진행: 로비, 방, 다운 흐름, 작전 시계, 결과 카드, 최종 결과 |
| `versus/vsengine.js` | 같은 입력으로 한 다운을 다시 계산(`runDown`) + 기기 비교 시험 100개 |
| `versus/vs.css` | 대전 화면 스타일 |
| `versus/fbconfig.js` | Firebase 설정값 |
| `firebase/database.rules.json` | 보안 규칙 (방·다운·비공개 수비 선택 추가) |

`index.html`·`board.html`·`apps-script/`는 바꾸지 않았다. `index.html`을 고치면 `tools/build_versus.py`를 다시 돌려 `versus.html`을 새로 만든다.

## 선생님이 먼저 할 일: 규칙 다시 게시
Firebase 콘솔 → Realtime Database → **규칙** → `firebase/database.rules.json` 내용을 통째로 붙여 넣고 **게시**.
(안 하면 방을 만들 때 "PERMISSION_DENIED"가 나온다.)

## 시험 순서 (혼자, 웨일북 2대 + 아이폰)
1. **기기 비교** — 웨일북 1대와 아이폰에서 `versus.html?test` → [시험 시작]. 두 기기의 **결과 코드**가 같은지 본다.
   (이 컨테이너의 Chromium 결과: 결과 코드 `501607BB`, 정밀 코드 `7FAADAE9`. 정밀 코드는 달라도 결과 코드가 같으면 경기에는 문제없음)
2. **대전 한 판** — 웨일북 A에서 `versus.html` → [새 방 만들기] → 4자리 번호. 웨일북 B에서 번호 입력 → [들어가기].
3. 공격 쪽/수비 쪽을 번갈아 조작하며 한 판 끝까지. 끝나면 두 기기의 **승패·점수가 같아야** 한다.
4. 해 보면 좋은 것: 수비 위장 1번, 런 플레이 1번, 3D로 플레이 1번, 중간에 한 기기 새로고침(같은 다운으로 돌아와야 함), 작전 시계를 그냥 흘려보내기(수비 15초·공격 40초 자동 진행).
5. **보안 확인** — 두 기기 모두 `versus.html?debug`로 열면, 공격 쪽에 다운마다 "✓ 보안 확인: 스냅 전에는 수비의 실제 선택을 읽을 수 없어요"가 떠야 한다. ✗가 뜨면 규칙이 게시되지 않은 것.

## 여기서 확인한 것
- 기기 비교 100개: `index.html`과 `versus.html`의 결과가 같음(회귀 확인), 다시 돌려도 같음, 아이폰 화면 크기에서도 같은 코드.
- 두 브라우저로 한 판 전체 자동 진행(가짜 Firebase, 실제 규칙과 같은 '한 번만 쓰기·역할·비공개 선택' 흉내): 9다운, 위장 2번, 런·패스·추가 2점, 양쪽 새로고침, 양쪽 시간 초과 → 두 기기 점수 같음, 공격 결과와 수비 쪽 재계산 **불일치 0**.
- 실제 Firebase 규칙 자체는 여기서 실행하지 못했다(이 컨테이너에서 Firebase 접속·에뮬레이터 실행이 막힘) → 위 5번으로 확인.

## 설계서에 없던 부분, 이렇게 정했다
1. **방 만들기/들어가기** — 한 사람이 [새 방 만들기]로 빈 번호를 받고, 다른 사람이 그 번호로 들어간다. 이미 두 명이면 못 들어간다.
2. **결과 카드** — 두 기기 모두 [다음 ▶]을 눌러야 다음 다운. 30초 지나면 자동으로 누른 것으로 친다. 터치다운 뒤 추가점을 30초 안에 안 고르면 1점.
3. **다운 시작은 서버 시각** — 두 기기가 동시에 "시작"을 쓰려 해도 규칙이 첫 번째만 받는다.
4. **공격 중 새로고침** — 같은 다운의 플레이를 처음부터 다시 한다(던질 기회가 한 번 더 생김. 교실용이라 그대로 둠).
5. **한 기기가 아예 떠나면** 경기가 멈춘다. 끊김 30초 자동 진행은 M2에서(설계서 10절).
6. **수비가 고르는 동안 공격 화면**의 수비는 바로 전 다운에 실제로 나왔던 대형(드라이브 첫 다운은 2-2)을 보여 준다. 상황 칸에는 "고르는 중…".
7. **결과 불일치** — 수비 기기 계산이 공격 결과와 다르면 공격 쪽 결과를 쓰고, 결과 카드에 ⚠ 한 줄과 콘솔 경고를 남긴다.
8. 방은 아직 지우지 않는다(하루 뒤 정리는 M2의 교사 화면에서).

## 엔진에서 발견한 문제 (index.html, 고치지 않음)
런 플레이에서 핸드오프 뒤에 **3D 화면의 리시버 버튼**을 누르면 `throwTo()`가 `S.sim.sackT.toFixed`에서 오류가 나 플레이가 멈춘다(2D 필드는 이 경우를 막지만 3D 버튼은 안 막음).
대전에서는 `versus/vs.js`가 바깥에서 같은 조건으로 걸러 막았다. 혼자 하기(`index.html`)는 그대로이므로 수행평가 기간 뒤 고칠 것.
