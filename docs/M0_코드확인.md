# 설계서 1절 코드 확인 결과 (2026. 11. 19.)

`index.html`을 읽고 설계서 1절과 대조했다. 실행 비교(두 기기)는 아직 하지 않았다 → M1 첫 항목.

## 맞음
- `LEVELS[1]` 주전: `lag 0.30, ballReact 0.50, rush 3.0, rate 0.8, guide 'space', zones true` (그 밖에 `coach:true, disguise:0, mult:1.5`)
- `DRIVES=5, START_G=25, CONV_G={1:5,2:12}`, 1다운 TD +1
- `coach()` → `{actual, shown, say}`, 대형 키 `'2-2' '3-1' '4across' 'man' 'blitz'`
- `R.dt=0.05` 고정 간격, `simulate()`에 `Math.random` 없음 (3D 장식·`uid()`에만 있음)
- `throwTo()`의 던진 순간 `t = max(0.2, round(S.t*10)/10)` — **최소 0.2초**도 있음
- `newGame()` 기본 작전: spread, W1 go / W2 slant / W3 out / C hitch
- `encodePlay()/decodePlay()`, `PLAY_VER = 11`
- `GAME_STORE_URL = ''`, `STORE_URL_DEFAULT` = 수업용 Apps Script

## 다르거나 설계서에 더할 점
1. **`encodePlay()`는 선수 위치·길을 0.1야드로 반올림한다.** 끌어 놓은 위치는 소수점이 길어서, 공격 기기가 원래 위치로 계산하고 수비 기기가 코드로 계산하면 결과가 어긋날 수 있다.
   → 대전에서는 공격 기기도 스냅 때 `decodePlay(encodePlay())`로 반올림된 작전을 판에 다시 놓고 계산한다.
2. **`decodePlay()`는 화면을 건드린다** (모드 버튼 클릭, 3D 닫기, 칩·그리드 다시 그림, `clearSim()`). 리플레이용으로 쓸 때 순서 주의.
   또 코드 안의 `def`(당시 보이던 대형)로 `S.defKey`를 바꾼다 → 디코드 뒤 `S.defKey = actual`로 덮어써야 한다.
3. **`R`은 기기 상태에 따라 달라질 수 있다.** `R.rushArrive` 초기값은 `localStorage 'fg.rush'`(교사 설정)이고, 설정 창(⚙)에서 경기 중에도 바꿀 수 있다. `R.lag`는 `snapGame()`에서, `R.ballReact`·`R.rushArrive`는 `newGame()`에서 정해진다.
   → 대전에서는 매 스냅 직전에 `R.lag/ballReact/rushArrive`를 `LEVELS[1]` 값으로 강제하고, 설정 창의 러셔 값 변경은 막는다.
4. **결과는 `S.goal`에도 달려 있다.** `applyGoal(goal)`이 수비 구역을 줄이고, 런 길도 `S.goal`로 잘린다. → 다운 데이터에 `goal`(0.1 단위)을 함께 보낸다.
5. **`playOutcome()`에는 `td` 필드가 없다.** 반환은 `{k:'td'|'gain'|'inc'|'sack', gain, who?, how?, why?}`. 터치다운 판정은 `k==='td' || gain >= S.goal`(`gamePlayDone`). 설계서 5절의 `result` 모양을 이것으로 맞춘다.
6. **런 작전은 `throwTo` 말고도 끝나는 길이 있다.** 플래그·TD 순간에 `recordRun()`, 색은 `sackT+0.6`, 안 던지면 `R.T=5초` 끝. 모두 계산 결과로 정해지므로 입력은 `throw`(또는 null)만 있으면 된다. 런에서 QB가 라인 뒤면 던질 수도 있다.
7. **엔진이 `Math.hypot`·`Math.acos`를 쓴다.** 표준상 이 함수들은 브라우저마다 마지막 자리까지 같다는 보장이 없다. 웨일북·Chrome(같은 V8)끼리는 같을 가능성이 높지만, iPad(Safari)와 섞이면 판정 경계(쳐냄 1.0야드, 열림 3.0야드)에서 갈릴 수 있다. → 설계서 10절의 100개 비교에 iPad를 꼭 넣고, 어긋나면 "공격 쪽 값 채택" 규칙으로 처리.
8. 플레이 중 되감기(`scrub`)는 CSS로 `done` 단계에만 보인다 — 대전에서도 그대로 쓰면 된다.
